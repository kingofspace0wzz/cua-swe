Move and zoom on a ridge

Back to the maps

The magenta dot is a fixed geographic place on the 1400 m ridge. The initial camera center is on the 400 m side of the slope. The cyan dot is a nearby place on the same ridge. The grid, magenta and cyan dots are rendered map features, not contact indicators. Blue rings show the two contacts; the dashed ring shows their midpoint and remains as a reference after release.

Carry a place with the mouse

Press the center of the painted magenta ridge dot with the left mouse button. While holding the button, move the pointer: that same geographic place should stay under it at every held endpoint, not just move in roughly the same direction. The cyan companion and grid should move with the map, not stay behind while a contact indicator follows the pointer. Keep both dots inside the map.

  1. Start in a fresh, loaded pitched view. Grab the visible magenta dot, move a short distance sideways and down, and inspect the held endpoint. Still holding, move back sideways and a little up and inspect again. Pause to observe the stationary map before releasing. The accepted view should stay in place after release, rather than jump or drift.
  2. From that accepted view, complete the existing Move and zoom, Move 1, Move 2, Move 3, and Release sequence below. Without Reset, press the then-visible magenta dot, not its old screen position. Move it to two held endpoints with a change of direction, pause and release. Grab the dot again where it now appears and drag again. The new grab should continue from the accepted view, with no return to an earlier view.
  3. With no mouse button held and the touch demonstration released, use ordinary wheel zoom over the terrain map. Let the painted map finish moving. Find the magenta dot in this new view, then start a fresh mouse grab, inspect held moves, pause and release. Attachment and accepted-view retention should still hold.
  4. After completing the navigation above and releasing all contacts, choose Reset and wait for loaded terrain to appear again. The initial view should return. Press the now-visible magenta dot and make a short mouse drag with a change of direction, pausing at the held positions and before release. The dot should remain attached and the released view should stay accepted. Repeat in Native and Legacy; the reset views and this next grab should agree.

During a held mouse drag, only move or release the mouse; read-only observations may be taken while it is held. Do not click buttons, scroll or press keys during that drag. Finish wheel zoom before the next press, and always Release the touch demonstration before using the mouse. These are paused grabs, not flicks; no particular speed or short timing window is needed. Touch rotation and pitch are not part of this example.

Try the sequence with Native, then Legacy, using Reset only to start a fresh comparison. The integrations should agree. The independent flat map's drag and zoom buttons and all the existing touch demonstrations should keep working. An unavailable, ambiguous or clipped dot is not evidence of a navigation error; start a fresh comparison if you have navigated outside the demonstration area.

Try both navigation integrations

  1. Select Native, then Reset. Wait for loaded terrain to be rendered.
  2. Click Move and zoom. Two contacts are placed around the magenta ridge dot in the current view. They remain held; no movement happens yet.
  3. Click Move 1, Move 2, then Move 3. Each button holds its endpoint for inspection. The magenta place should stay at the midpoint, while the cyan place moves farther away as the map zooms in.
  4. Click Release. The accepted view should remain, without a jump. These examples pause before lifting, rather than flicking.
  5. Click Move and zoom again without Reset, then the three moves and Release. This continues from the resulting view, around the same geographic magenta place.
  6. Drag the terrain map with the mouse after release. Ordinary navigation should still work. Repeat the comparison using Legacy and Reset.

Both integrations should give the same visible results on the same terrain, including after release and a second demonstration. Changing integration does not reset the camera; use Reset when comparing from the initial view. Reset rebuilds the terrain on the same map. The small flat map is independent: drag it and use its zoom buttons to check ordinary navigation.

Disclosed contact replay

Buttons dispatch ordinary DOM touchstart, touchmove and touchend events to the map canvas. No touch-capable input device is needed. Contacts have IDs 11 and 22; every state is rendered before another button is enabled. Acquisition waits for the terrain and geographic sources to load and for two completed renders. There is no queued/burst input in this example.

The cyan companion is on the same level ridge, displaced along screen-right at this bearing. These horizontal, fixed-y moves should progressively increase the two geographic dots' painted separation. Perspective on elevated terrain means this need not equal the contact-separation ratio. Each held move should increase world-dot separation by more than 3 pixels, reaching at least 1.1, 1.2, and 1.3 times its starting distance, respectively (with a 3 pixel allowance). This checks visible zoom, not just translation of an overlay. Starting another demonstration uses the then-current magenta place and the same relative trace; it does not reset the map.

Observation allowances

Pixel sampling and terrain picking are quantized. The prospective checks allow 3 CSS pixels for attachment, accepted-view retention and world-dot separation, and 4 pixels for the Native/Legacy comparison. These are allowances, not a claim of measured calibration: a healthy mouse reference must validate the mouse allowance, and the retained touch comparison has its own control requirement. Missing, unloaded or clipped landmarks make an observation inconclusive. If ordinary navigation takes the ridge outside the demonstration area, Reset before starting another example. The trace below the map lists the dispatched contacts.

Integration API

This is an explicit synthetic integration extension, not an existing upstream plugin regression. Native uses the real Terrain queries. Legacy exposes three bound query delegates from that same real Terrain; it does not replace the renderer or terrain data. API signatures and coordinate/elevation units describe the supported query objects. The local asset and geographic description is in manifest.json.

MapLibre GL JS is provided under its license. The example's local synthetic Terrarium assets do not require an external tile service.
