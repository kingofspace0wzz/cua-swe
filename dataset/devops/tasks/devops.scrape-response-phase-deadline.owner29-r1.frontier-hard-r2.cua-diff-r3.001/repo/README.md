# Scrape Harbor

Original staging scraper/exporter investigation. Run `npm run build` then `CUA_SWE_EXTERNAL_SERVICE_ORIGIN=<staging origin> node server.mjs --port 56510` through the supplied runtime. The staging origin is supplied by the launcher. The collector uses native HTTP, parses complete Prometheus text bodies, and submits parsed samples to the receiver.

`src/scrape.mjs` owns HTTP request lifetime. `src/budgets.mjs` holds ordinary millisecond budgets. `src/metrics.mjs` parses bodies and `src/collector.mjs` submits samples. The transport budgets are regular function inputs, including for transport tests; there is no special repair setting. Budget constants in this repository are ordinary collector inputs carried over from earlier flat-objective rollouts. The build and public bridge entrypoints are harness-controlled and readable.

The staging service assigns every scrape target a per-rollout collection tier, a receiver class and a profile code, and reports the rollout's current policy activation epoch. The console displays the profile code, the live activation epoch, each target's current tier and receiver-class assignment, native phase timeline, completed-attempt evidence, and the receiver team's ordinary operations publications supplied by the external service as rendered images. Tier and receiver-class assignments, activation schedules, policy revisions, objective envelopes, approved collector caps, and compliant receipt examples belong to the staging service and change between rollouts and activation epochs; nothing in this repository pins them, names them, or bounds how the service spells its tokens. The `/begin` target descriptors carry the profile, epoch, tier and receiver-class tokens needed by the collector after an operator has consulted the receiver publications. A 30 ms measurement allowance covers the local wire/clock observation boundary. The published values are service objectives and approved response bounds, not a protocol secret. Whatever bounds a request must cover connection, final response headers and body EOF, including trickle traffic. Preserve complete payloads, healthy targets, last-success timestamps and truthful failures. Diagnostic sample age is measured at ingestion, not a continuous periodic freshness promise.

Use Run scrape checks and optionally open a target detail. The console displays actual producer HTTP records, receiver receipts, retained attempt history, and the receiver team's current publications. Exact deployed response delays, activation schedules, profile/tier/receiver-class assignments, published objective numbers and sample values belong to the external staging service and are inspectable through normal operator screenshots. No automatic retry policy, label merging, sampling window or secret protocol is involved.
